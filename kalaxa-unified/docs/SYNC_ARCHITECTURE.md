# معماری اتصال‌پذیری — تصمیم‌های Sync (v2.2.0)

نیاز کارفرما: اتصال آیندهٔ پلاگین به وب‌سایت (kalaxa.ir) و اپ‌های اندروید/iOS/ویندوز.
اصل راهنما: **هستهٔ آفلاین دست‌نخورده می‌ماند؛ اتصال‌پذیری فقط یک مرز است، نه بازطراحی.**

| کد | تصمیم | دلیل |
|---|---|---|
| D-SYNC-1 | متادیتای sync (`revision`, `updated_at`, `device_id`) در **سطح پاکت**، اختیاری، خارج از `doc` | چک‌سام سند و goldenها هرگز تغییر نمی‌کنند؛ پاکت‌های قدیمی بدون sync معتبر می‌مانند؛ مهاجرت لازم ندارد |
| D-SYNC-2 | offline-first، تشخیص واگرایی با `revision` + `checksum`، حل تعارض **دستی** (last-write-wins با هشدار)؛ merge خودکار ممنوع | برای سند طراحی کابینت، merge خودکار خطرناک و بی‌ارزش است |
| D-SYNC-3 | پلاگین فقط با `Adapter::SyncPort` (push/pull/status روی پاکت خام) حرف می‌زند؛ پیاده‌سازی HTTP بیرون از هسته | هسته آفلاین و تست‌پذیر می‌ماند؛ CSP/سیاست بدون‌شبکه نقض نمی‌شود |
| D-SYNC-4 | فاز اول سرور: REST endpoint در قالب پلاگین وردپرس روی kalaxa.ir (احراز هویت: application password)؛ کلاینت‌ها **read-only** شروع می‌کنند | بدون سرور جدید؛ ارزش فوری (نمایش نقشه/گزارش به مشتری و نصاب) با کمترین ریسک |

## چرا کلاینت‌ها ارزان درمی‌آیند
موتورهای آنالیز همگی UMD و بدون وابستگی‌اند (`kalaxa/ui/kalaxa-*.js`) و همین حالا در Node تست می‌شوند.
همان فایل‌ها بدون تغییر در وب‌اپ، WebView اندروید/iOS و اپ ویندوزی اجرا می‌شوند؛
کلاینت فقط باید: پاکت را از SyncPort بگیرد → چک‌سام را تأیید کند → با
`kalaxa-doc-adapter.js` به `kitchen_snapshot` تبدیل کند → موتورها را صدا بزند.
راستی‌آزمای مستقل پایتون (`tools/verify_data_spec.py`) اثبات می‌کند مشخصات
Canonical/چک‌سام در هر زبانی (بک‌اند PHP/Python/Kotlin/Swift) بازپیاده‌سازی‌پذیر است.

## قرارداد سیم (wire)
```json
{
  "format": "kalaxa-doc",
  "schema_version": 3,
  "checksum": "sha256(canonical(doc))",
  "doc": { ... },
  "revision": 12,
  "updated_at": "2026-07-23T08:00:00Z",
  "device_id": "sketchup-<uuid>"
}
```
- خواننده‌ها کلیدهای پاکتیِ ناشناخته را نادیده می‌گیرند (سازگاری رو به جلو).
- `revision` سمت مبدأ پس از هر ذخیرهٔ موفق +1؛ سرور هرگز آن را بازنویسی نمی‌کند،
  فقط بزرگ‌ترین را نگه می‌دارد و در `status` گزارش می‌دهد.

## خارج از محدوده (عمداً)
- هیچ کد HTTP در این مخزن؛ پیاده‌سازی وردپرسی، مخزن جداست.
- merge خودکار، sync زنده، و ویرایش از کلاینت‌های موبایل — پس از تثبیت read-only.
