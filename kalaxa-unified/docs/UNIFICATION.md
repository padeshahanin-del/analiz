به دستور کارفرما: «کابینت‌یار جدا نیست؛ جفتش کالاکساست» — یک محصول واحد.

| موضوع | تصمیم | دلیل |
|---|---|---|
| فضای نام | `Kalaxa`، پوشه `kalaxa/`، dict `kalaxa` | برند واحد |
| هسته | معماری کابینت‌یار عیناً (app/domain/persistence/adapter/i18n) | لایه‌بندی تمیزتر، Canonical+چک‌سام، تست Ruby موجود |
| Logger | فقط `App::Log` کابینت‌یار؛ logger لایه آنالیز حذف و فراخوانی‌ها مهاجرت داده شد | یک مسیر log |

| UI | پنل آنالیز = پنل اصلی؛ پنل پایه bridge برای تست پل/زبان در منو حفظ شد (تست‌های رینگ B/C به آن وابسته‌اند) | بدون دور ریختن پوشش تست |
| format پاکت | `kalaxa-doc` + پذیرش میراثی `kabinetyar-doc` | داده قدیمی نسوزد |

| ENV | `KALAXA_DATA_DIR`، `KALAXA_QUIET` | هم‌نام برند |
| دو قرارداد داده | هر دو زنده: سند دامنه (منبع حقیقت طراحی) و kitchen_snapshot (قرارداد آنالیز)؛ پل = `kalaxa-doc-adapter.js` | جدایی مسئولیت + ۲۰۴ تست موجود دست‌نخورده |
| اسکنر میراثی | dictionary قدیمی `kalaxa_cabinet` همچنان اسکن می‌شود | مدل‌های موجود کارفرما |

## Unverified (نیازمند اجرای کارفرما)
کل Ruby (بوت، منو، پل، ذخیره‌سازی داخل اسکچاپ) + تست‌های Minitest/TestUp پس از تغییرنام. توجه: تست‌های Minitest تغییرنام‌یافته‌اند و `require_relative` هایشان باید با چیدمان جدید (`kalaxa/…`) سالم باشد — اولین اجرای `ruby test\unit\test_phase01.rb` این را قطعی می‌کند؛ در صورت خطای مسیر، متن خطا را بفرستید.

## D-HW-1 (v2.3.0) — ادغام یراق صریح با BOM قاعده‌محور
سیاست: **صریح بر قاعده غالب است، به تفکیک (کابینت، نوع)**. آداپتور یراق سند را
به‌صورت `explicit_hardware` در خروجی خود (نه داخل snapshot — قرارداد snapshot دست‌نخورده)
عبور می‌دهد؛ `KalaxaHardware.bom(snapshot, {explicit})` سهم قاعده‌محور همان نوع را برای
همان کابینت حذف و ردیف صریح (با نشان «صریح از سند» + sku) را جایگزین می‌کند؛
نوع‌ها و کابینت‌های بدون یراق صریح با قاعده پر می‌شوند. qty نامعتبر خطای صریح آداپتور است.
نگاشت نوع: hinge/handle/leg مستقیم، slide→ریل، connector→مینی‌فیکس+دوبل، ناشناخته→فقط ردیف مستقل.
