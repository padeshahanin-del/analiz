# بردن کالاکسا روی دستگاه دیگر

دو کار کاملاً متفاوت است و با هم قاطی نشوند:

- **الف) فقط می‌خواهم افزونه آن‌جا کار کند** — کاربر، کارگاه، مشتری.
- **ب) می‌خواهم آن‌جا هم روی خودِ پروژه کار کنم** — توسعه.

---

## الف) فقط اجرای افزونه

۱. فایل `dist/kalaxa-<نسخه>-release.rbz` را ببرید (همین یک فایل، ~۳۰۰ کیلوبایت).
۲. در اسکچاپ: `Extensions → Extension Manager → Install Extension` و همان فایل
   را بدهید.
۳. اسکچاپ را ببندید و باز کنید.

**اکانت ویندوز فرقی نمی‌کند.** افزونه در پروفایل همان کاربری نصب می‌شود که
اسکچاپ را اجرا می‌کند. هیچ لایسنس، هیچ فعال‌سازی و هیچ اتصال اینترنتی لازم
نیست — افزونه کاملاً آفلاین است.

### اگر تنظیمات و انبار آفکاتتان را هم می‌خواهید

این‌ها **کنار افزونه نیستند**، در پروفایل کاربر ویندوزند:

```
%APPDATA%\Kalaxa\
```

سه فایلی که ممکن است آن‌جا باشد:

| فایل | چیست | بردنش لازم است؟ |
|---|---|---|
| `settings.json` | تنظیمات کارگاه (ضخامت، نوار، قیمت‌ها) | اگر می‌خواهید همان تنظیمات را داشته باشید، بله |
| `offcut_inventory.json` | انبار آفکات | فقط اگر انبار همان کارگاه است |
| `kalaxa.log` | لاگ | نه |

روی دستگاه تازه همان پوشه را بسازید و فایل‌ها را کپی کنید. اگر نبرید،
افزونه با پیش‌فرض‌ها بالا می‌آید — چیزی خراب نمی‌شود.

### پیش از حذف نسخهٔ قدیمی روی دستگاه فعلی

از منوی کالاکسا **«بستن پنجره‌های کالاکسا (پیش از حذف افزونه)»** را بزنید،
بعد حذف کنید. پنجرهٔ باز، فایل‌های پوشهٔ پلاگین را در دست دارد و حذف آن
پوشه زیر پای پنجرهٔ زنده، اسکچاپ را می‌بندد.

---

## ب) ادامهٔ توسعه روی دستگاه دیگر

### چه چیزی را ببرید

کل پوشه، **جز `dist/`**. آن‌جا ۷۰+ بستهٔ قدیمی است و بیشترِ حجم پروژه را
می‌گیرد؛ فقط آخرین `.rbz` را نگه دارید یا هیچ‌کدام را (با یک فرمان دوباره
ساخته می‌شود).

```
kalaxa/     kalaxa.rb     test/     tools/     docs/
CHANGELOG.md            README.md
```

### چه چیزی لازم است نصب باشد

فقط دو تا، و هیچ‌کدام وابستگیِ پروژه‌ای ندارند:

- **Ruby** ۲٫۷ یا بالاتر (`gem install minitest`)
- **Node.js** ۱۴ یا بالاتر

`package.json` و `node_modules` وجود ندارد و لازم هم نیست — ماژول‌های
جاوااسکریپت UMD خالص‌اند و فقط با `node` اجرا می‌شوند. هیچ gem بیرونی جز
`minitest` لازم نیست.

### اولین کاری که آن‌جا می‌کنید

```
ruby tools/check_env.rb
```

خودش می‌گوید چه چیزی کم است — روبی، نود، minitest، کاتالوگ‌های داده و
دادهٔ کاربر را بررسی می‌کند. راهنما کهنه می‌شود، این اجرا می‌شود.

بعد:

```
ruby tools/run_all_tests.rb        # همهٔ تست‌ها
ruby tools/run_all_tests.rb system32   # فقط یک دسته
ruby tools/build_rbz.rb            # ساخت بسته
```

### چیزی که به این دستگاه گره نخورده

هیچ مسیر مطلقی در کد نیست. تنها مسیر بیرونی `%APPDATA%\Kalaxa` است که
خودش ساخته می‌شود، و با متغیر محیطی `KALAXA_DATA_DIR` قابل تغییر است
(تست‌ها از همین استفاده می‌کنند).

این ادعا آزمایش شده است: کل پروژه در مسیر دیگری کپی شد، هر ۷۶ فایل تست
سبز ماند و همان بستهٔ RBZ با همان حجم ساخته شد.

### یک کمبود که باید بدانید

**این پوشه مخزن گیت نیست.** یعنی تاریخچه‌ای برای بردن وجود ندارد و اگر
روی دو دستگاه هم‌زمان کار کنید، هیچ چیزی تغییرات را با هم آشتی نمی‌دهد —
دستی باید فایل‌ها را جابه‌جا کنید و آخرین کپی برنده است.

اگر قرار است روی دو دستگاه کار کنید، پیش از انتقال:

```
git init
git add .
git commit -m "Kalaxa <نسخه>"
```

و یک مخزن خصوصی (گیت‌هاب، گیت‌لب یا حتی یک درایو مشترک) وسط بگذارید.
`dist/` را در `.gitignore` بگذارید.
