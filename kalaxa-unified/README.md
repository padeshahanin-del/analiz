# کالاکسا | Kalaxa

افزونهٔ اسکچاپ برای طراحی پارامتریک کابینت، کمد و کتابخانه — به فارسی، برای
کارگاه ایرانی. لیست برش، بهینه‌سازی ورق، نقشهٔ CNC، نقشهٔ نصب، نمای انفجاری،
فهرست کالا و خروجی اکسل. **کاملاً آفلاین**؛ نه لایسنس، نه اتصال اینترنت.

نسخهٔ فعلی: **۳٫۶۹٫۰** — اسکچاپ ۲۰۲۳ تا ۲۰۲۶

---

## نصب (کاربر)

فایل `dist/kalaxa-<نسخه>-release.rbz` را در اسکچاپ از مسیر
`Extensions → Extension Manager → Install Extension` نصب کنید، بعد اسکچاپ را
ببندید و باز کنید.

> **پیش از حذف افزونه** از منوی کالاکسا «بستن پنجره‌های کالاکسا» را بزنید.
> پنجرهٔ باز فایل‌های پوشهٔ پلاگین را در دست دارد و حذف آن پوشه زیر پای
> پنجرهٔ زنده، اسکچاپ را می‌بندد.

## توسعه

```bash
ruby tools/check_env.rb        # اول این — می‌گوید چه چیزی کم است
ruby tools/run_all_tests.rb    # ۷۶ فایل تست (۳۴ روبی + ۴۲ جاوااسکریپت)
ruby tools/build_rbz.rb        # ساخت بستهٔ نصب
```

فقط **Ruby ۲٫۷+** (با `minitest`) و **Node ۱۴+** لازم است. `package.json` و
`node_modules` ندارد و لازم هم نیست.

### ساختار

| مسیر | چیست |
|---|---|
| `kalaxa.rb` | بارگذارِ افزونه (`SketchupExtension`) |
| `kalaxa/lib/` | ۱۲ موتور روبی — هندسه، لیست برش، بخش‌بندی یونیت، سوراخ‌کاری |
| `kalaxa/ui/` | ۳۷ ماژول جاوااسکریپت (UMD) — نستینگ، نقشه‌ها، گزارش‌ها |
| `kalaxa/data/` | ۱۰ کاتالوگ JSON — **تنها منبع حقیقت**، هر دو زبان از همین می‌خوانند |
| `kalaxa/dev/tests/` | تست‌های جاوااسکریپت |
| `test/unit/` | تست‌های روبی (با استاب اسکچاپ در `test/stubs/`) |

### دو قاعده که این پروژه با آن‌ها ساخته شده

**۱. واگرایی باید ناممکن باشد، نه فقط قابل تشخیص.**

باگِ غالبِ تاریخ این پروژه یک شکل داشته: **نویسنده و خواننده هم را نمی‌بینند
و هر دو جداگانه سبزند.** فرمول تراز طبقه در چهار جا حساب می‌شد؛ کاتالوگ ورق
در روبی و جاوااسکریپت جدا نوشته شده بود؛ ردیف قید در مدل بود و در لیست برش
نبود. جواب، تست آینه‌سنجی نیست — تست واگرایی را می‌گیرد ولی جلویش را
نمی‌گیرد. جواب این است که **یک** منبع باشد: کاتالوگ‌های JSON مشترک و توابع
تک‌منبعی.

**۲. تستی که اولین بار سبز شود هنوز چیزی ثابت نکرده.**

هر نگهبان تازه با جهش‌کاشتن آزموده می‌شود: کد را عمداً خراب کن و ببین تست
می‌افتد یا نه. چند بار همین کار نشان داد تستی که نوشته بودم تهی است — مثلاً
فاصلهٔ آزادِ سوراخ اتفاقاً برابر گام بود، پس دو رفتار متفاوت یک جواب
می‌دادند. اگر جهشی زنده ماند، یا تست ضعیف است یا آن کد لازم نیست.
